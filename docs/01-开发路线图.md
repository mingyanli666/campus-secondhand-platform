# 开发路线图

按"地基 → 核心业务 → 交互业务 → 管理后台 → 打磨"的顺序推进。
**顺序不要乱**：先把公共能力（统一返回、异常、鉴权、跨域）做好，后面每个功能只需要写业务本身。

## 关键设计约定

1. **统一返回格式**：所有接口返回 `Result<T>`，`code` 为 0 表示成功（或 200，本项目统一用 200）。
2. **统一异常**：业务错误抛 `BusinessException`，由 `GlobalExceptionHandler` 统一转成 `Result`。
3. **鉴权**：登录后前端把 `token` 放在 `Authorization` 请求头；拦截器解析后放入 `UserContext`。
4. **越权防护**：需要登录的接口默认拦截；管理员接口加 `@RequireRole("ADMIN")` 注解。
5. **逻辑删除**：含 `deleted` 字段的表走 MyBatis-Plus 逻辑删除；用户表用 `status` 控制。
6. **状态机**：商品状态、订单状态只允许按定义好的路径流转，非法流转直接抛异常。
